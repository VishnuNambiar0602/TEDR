AIR-DETR Project Overview

Adaptive Inference RT-DETR using AirLLM-style Weight Streaming & Multi-Level Quantization

Slide 1: Project Overview & Core Problem

AIR-DETR is a high-performance computer vision project focused on deploying Real-Time Detection Transformers (RT-DETR) in resource-constrained or edge environments[cite: 54]. By adapting design paradigms typically used for running large language models on consumer hardware (such as AirLLM), this framework allows massive model evaluation with reduced peak hardware requirements[cite: 54].

Key Features & Targets:

  • Domain-Specific Application: Configured out-of-the-box for customized automated traffic detection pipelines, specifically trained on custom vehicle groups like the coco_autorickshaw dataset[cite: 1, 55].
  • Hardware Acceleration & Agility: Orchestrated via Docker stacks with customized native GPU scheduling allocations (NVIDIA Docker runtime layers)[cite: 50, 51].
  • Execution Interfaces: Includes standard Make environments, standalone Windows batch configurations (run_app.bat), and modular Python scripting frameworks[cite: 1, 53].

Slide 2: Architectural Framework & Directory Map

The system splits code layout transparently between application modules, execution scripts, core dataset classes, and structural benchmark trackers[cite: 1].

Core Engine Organization:

Slide 3: Technical Components Deep-Dive

The project achieves its localized memory reduction goals using a multi-pronged optimization pipeline[cite: 54]:

1. Layer-Wise Weight Streaming Scheduler

Inspired by AirLLM, the WeightStreamingScheduler handles rapid SSD → RAM → GPU prefetching queues[cite: 54]. Layers are loaded and purged dynamically during the execution of a single inference forward pass, bypassing the need to pin the entire parameter footprint permanently inside processing memory[cite: 54].

2. Quantization Manager Engine

Implements multi-level Post-Training Quantization (PTQ) utilities (INT8/INT4 pack/unpack functions)[cite: 54]. It interfaces directly with advanced evaluation heuristics:

  • Calibrated Quantization: Uses representative batches to protect activation scales against saturation distortion.
  • AWQ & GPTQ Pipelines: Advanced second-order parameter tracking mechanisms built to protect critical weights from collapsing during aggressive sub-byte compression rounds[cite: 77, 78].

3. Resource and VRAM Boundary Manager

The system leverages a specialized VRAMManager to act as a software barrier, continually verifying hardware bounds and preventing Out-Of-Memory (OOM) failures by coordinating directly with layer eviction modules[cite: 54].

Slide 4: Log Tracking & Phase Transformations

The performance profile of the framework evolves drastically based on the optimization strategies applied across experimental phases:

Phase 1: Pure Native RT-DETR Baseline Performance

The standard baseline model maintains predictable structural processing constraints, demanding full model residency inside GPU VRAM[cite: 77, 78]. This ensures maximal target detection accuracy but scales poorly when scaled up to extra-large parameter counts[cite: 77, 78].

Phase 2: Transitioning to Weight Streaming (AIR-RT-DETR)

Activating the StreamingRTDETR module updates the model's standard forward pass routine[cite: 54]. By loading shards sequentially, it introduces a massive drop in peak memory footprint without compromising any accuracy metrics[cite: 77, 78].

Phase 3: Multi-Level Advanced PTQ Integration

Adding techniques like calibrated configurations, AWQ, and GPTQ aims to lower the dynamic memory overhead of individual layer activations even further[cite: 77, 78]. However, as shown in the benchmark results, standard sub-byte roundings (like plain INT4) can cause massive accuracy degradation in localized vision models if deployed without specialized architectural adaptations[cite: 77, 78].

Slide 7: Cross-Model Comparison & Strategic Takeaways

Analyzing behavioral patterns between the RT-DETR-L and RT-DETR-X deployment runs highlights several critical optimization insights[cite: 77, 78]:

1. The VRAM Compression Triumph

  • RT-DETR-L: Drops peak VRAM from 1609.6 MB down to 727.6 MB (~54.8% savings)[cite: 77].
  • RT-DETR-X: Drops peak VRAM from 2338.2 MB down to 826.4 MB (~64.6% savings)[cite: 78].
  • Takeaway: Streaming architectural patches cleanly isolate memory scaling issues. Larger model frames gain proportionately higher resource savings when passing layers dynamically through shared execution bounds[cite: 77, 78].

2. Throughput & Latency Anomalies

  • In both model test groups, activating STREAMING_FP32 actually increased throughput (FPS) and reduced processing latency compared to their native baselines[cite: 77, 78].
  • This performance improvement suggests that bypassing full memory context footprints streamlines system caching layers and avoids system-wide memory bus contention overheads[cite: 54, 77, 78].

3. Quantization Evaluation and Behavior

  • L-Variant: Highly sensitive to quantization steps; dropping directly to INT4 zeroes out model detection capabilities completely[cite: 77].
  • X-Variant: Displays much stronger resiliency under compressed environments[cite: 78]. Under second-order GPTQ steps, the X-Variant reaches an optimal 36.58% mAP50, paired with the fastest inference speed in its class (4.14 FPS)[cite: 78].
